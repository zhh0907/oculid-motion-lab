# 固定患者与实时眼位轨迹

版本 0.5，2026-10-28。

## 使用

1. 首页右侧“模拟患者”选择双眼同向受限、单眼内转受限或单眼外转受限，再选左右侧。此时立即运行明显示例；同向受限的侧别指运动方向，单眼模板的侧别指受累眼。
2. 展开“批量生成患者”，填写数量，例如 30，再点“生成并固定”。生成后自动调用第一位。种子留空时每批使用新的随机种子；需要重复一组抽样时可指定同样的种子、数量、模板和侧别。
3. 输入 `17` 或 `P000017` 调用患者，也可用上一位/下一位切换。同一患者的参数始终固定；重新开始、切换路径、输入源、控制器或眼睑外观都不会重新抽样。更改模板或侧别则切换到该类型的明显示例。
4. “患者库”内可导出备份，或导入原 Binocular Motion Lab 的患者库 JSON。首页和 Oculid 完整工作台共用本系统的浏览器患者库；原站点的库不会自动覆盖到此处，需显式导入。不同库可能都有 P000017，所以跨设备使用时要携带对应的库文件。

有冲突的同号配置不会覆盖旧患者；不同的非空库不能直接混合。不可读的本地数据保留等待有效备份恢复。另一标签页修改了库时，本页不覆盖它，会提示先导出再刷新。浏览器不能保存时，患者仍能在当前页运行，但需关闭前导出。

## 模型与随机抽样

继续使用原有 `horizontal-capacity-v1`、原始运动控制器及三种模板，没有新增神经病损或医学分级。容量参数在原范围 0.12–0.88 的三个等宽区间中均衡抽样，30 人对应每段 10 人；编号顺序与强弱分段打散。患者参数冻结，运行中没有逐帧疾病随机噪声。

明显示例使用原来的强限制参数，新增右侧镜像示例分别有自己的标识。它们不占用编号患者库。批量生成中的三个抽样区间**不等于 NIHSS 0/1/2**，也不能保证医生最后打分的类别平衡。仍需医生判断真实性和评分。

## 即时眼位滑轨

眼部画面下面首先显示两条独立水平轴，L / R 与上方 3D 视图的通道顺序一致。眼球标记只显示此刻位置，在轴上左右滑动；空心圆为同一正常控制器的参考位置。原有时间/二维轨迹图位于下方。

横轴使用眼角半宽归一化的位置，0 为眼角中点。正值朝画面右侧，与本模拟器的 3D 视图一致。这里从眼球角度和当前几何计算：`u = 0.01255 × sin(yaw) × cos(pitch) / 0.0132`，角度代入三角函数前转换为弧度。这对应当前正交视图中的瞳孔中心横坐标除以眼裂半宽，**不是从摄像头或渲染图像重新识别的眼位**。也没有沿用 GazeLab 的受试者左侧为正的符号约定。

暂停或食指丢失时，标记与 3D 眼球共同保持。眨眼或其他眼睑遮挡时仍显示模拟真值，但以虚线、淡色眼球和遮挡文字提示。绘图直接读取当前帧，不引入新的病症噪声、角度增益、评分或独立动画时钟。

## 轨迹图

- 默认“水平随时间”，也可以切换“垂直随时间”和“二维眼位 · 水平 / 垂直”。二维视图横纵轴使用相同的每度像素长度，避免拉伸运动形状。
- 绿色对应 L 眼，蓝色对应 R 眼。实线是经过患者层后的眼位，虚线是同一输入下、经过同一正常控制器而未加患者层的参考。
- 时间是仿真秒，眼位是角度（°）。水平正值为受试者右侧，垂直正值为向上。这里沿用模拟器坐标；GazeLab 原图中的归一化眼位及其符号不能直接当作本图角度。
- 图显示最近 20 秒，以 50 Hz 记录图表样本、最多 20 Hz 重绘；模型及导出样本仍为 250 Hz。较快运动的显示受到图表抽样限制，精细分析请使用导出数据。
- 暂停或食指丢失会冻结仿真和图表；重新捕获食指后另起一段曲线。图中的断段不表示新增患者病症。
- “清除轨迹”仅清图，不改变患者、仿真时间或导出记录。重开运行或更换患者则开始新的记录，避免混合不同患者的数据。超过 120 秒后导出记录停止增加，但实时图继续滚动。
- 图显示模拟角度真值。闭眼时仍能画出眼球运动，这不代表图像追踪器能透过眼睑测到瞳孔。

## 导出与验证

当前运动 JSON 保留完整患者配置、库 ID、模型版本、患者层初始状态及每个 250 Hz 样本的正常参考和输出。按初始状态逐样本重放原 `PatientLayer` 可复现输出。CSV 追加患者编号、库 ID、模板和侧别；患者库 JSON 用于跨设备恢复编号。

34 项 Node 测试通过，包括六种左右示例、固定患者重放、保存冲突保护以及图表持续运行。浏览器验证覆盖生成 30 人、编号调用、刷新、换控制器、跨工作台共享、导入/导出、三种图表、清图、暂停、食指丢失/恢复及 320/390/844 像素布局。摄像头自动化仍为输入接口注入，未重新测量实体摄像头精度。
