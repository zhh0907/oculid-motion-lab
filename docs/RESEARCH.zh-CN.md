这些项目的能力陈述来自上列原始来源。下述组合架构是本项目的工程判断，并不是上述作者提出或验证的统一方案。

## 选择的架构

输入目标 → 原有控制器 → 原病例运动层 → 四个眼球角度 → 眼睑外观层 → 渲染。

两种 GRU、几何函数、病例模型、相机投影与手部追踪代码来自现有 Binocular Motion Lab。眼睑读取眼球 pitch，但不写回控制器。眼皮遮住瞳孔时，真实的模拟眼球角度仍然存在，输出的数据也保留它。

原始文件的 SHA256 和基线提交记录在 `upstream-manifest.json`。病例库和标定配置仅更换 localStorage 命名空间，避免同一 GitHub Pages 域名下与旧项目共享存储；测试会逆转该字符串替换再核对原文件哈希。已有病例和标定可通过原来的 JSON 导入功能迁移。

## 当前实现

- 12.4 mm 外观眼球半径、64 mm 默认双眼间距；每只眼保持 yaw 与 pitch 两自由度。
- 上下眼睑由贴合眼球的连续三维网格构成，附眼睑边缘、简化泪阜、睫毛、眼周和鼻梁。
- 垂直及水平注视带动眼睑，加入不同速度的跟随滞后、鼻侧组织滑动和褶皱恢复；支持眼裂开合及左右独立的上睑覆盖量。
- 可重复的非等间隔自动眨眼，平均间隔约 4.6 秒；基础时序为 85 ms 闭合、30 ms 停留、205 ms 张开，每次施加确定性时长变化；上睑承担 90% 闭合行程。这些数值是可修改的工程预设，**未由人体数据拟合**，不应当作人群生理标准。
- 程序化虹膜、可调瞳孔、简化角膜高光和肤色。未使用真人面部照片。
- 正面正交视图下，通过瞳孔圆盘采样计算几何可见比例；它不是图像追踪算法的输出，也不支持任意视角的可见性测量。
- `workspace.html` 保留原模型、病例库、公共数据回放、导出及相机/屏幕标定。该页面的历史导出格式保持兼容；首页的新格式额外记录眼睑。

## 如何解释“跟之前一样追踪”

1. **目标驱动相同**：对相同输入、相同初始状态、相同模型与病例参数，眼球角度应逐样本一致。原项目直接生成的 3,600 个基准样本验证了这一点。
2. **摄像头食指输入兼容**：继续使用原 MediaPipe 手部检测、映射、平滑和丢失时保持策略；仿真时钟在丢失期间停止。自动化测试向相机接口注入已知目标，并验证权限失败、丢失与恢复。没有测试实体相机精度。
3. **外部算法从渲染图像识别眼睛**：本版不保证。眼睑遮挡会减少瞳孔信息；完整闭眼时，图像观察不到瞳孔，不能把隐藏的角度真值伪装成检测结果。原本需要整张脸的追踪器也不一定接受局部眼周图像。

## 尚未验证与后续验收

当前结果是可运行的程序化眼部模拟，不是扫描级写实人脸或已验证的生理眼睑模型。未模拟角膜真实折射、泪膜光学、瞳孔对光反射、眼外肌、眼球扭转、Bell 现象或头部运动；也不把既有眼球模型的误差指标迁移到新增眼睑。

如果下一阶段目标是训练/评测图像追踪器，需要：固定相机和照明；采集或取得合适许可的真人眼睑数据；测量眼睑轮廓误差、眨眼时序误差、虹膜/瞳孔分割 IoU、可见帧的角度误差、遮挡丢失率和重新捕获延迟。须分别报告无遮挡、部分遮挡、完全闭眼的结果，并用受试者独立的数据检验泛化。若目标是更接近摄影图像的外观，优先用可替换的 glTF 眼周网格/形变目标和有明确许可的材质，保持同一个角度接口。
